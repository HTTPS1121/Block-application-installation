# שומר אפליקציות — איפיון מוצר

**פלטפורמה:** Android (יעד: Pixel / AOSP, API עדכני)  
**מודל הרשאות:** Device Admin + Accessibility + Usage Access + Overlay — **בלי** Device Owner / factory reset  
**השראה התנהגותית:** Kaspersky Safe Kids על Pixel (שכבת UX + Accessibility), לא Knox

---

## 1. מטרה

אפליקציית הורה/מגן על מכשיר אישי:

1. **רשימה מותרת** — מצב ההגנה **היחיד**. רק אפליקציות מסומנות נפתחות. אין «ממתין לאישור» ואין «רמה 2». אפליקציה חדשה פשוט לא ברשימה → חסומה.  
2. **הגנה עצמית** — מקשה על הסרה / ביטול הגנה בלי קוד ניהול (סגנון קספרסקי).  
3. **תמיד ניתן לפתוח את השומר עצמו** עם קוד ניהול / קוד שחזור — לעולם לא נעילה עצמית.

---

## 2. זהות ואבטחת כניסה

| פריט | התנהגות |
|------|---------|
| קוד ניהול (PIN) | 4–8 ספרות, מוגדר בהתקנה ראשונה |
| קוד שחזור | נוצר פעם אחת בהגדרה, מוצג לצילום מסך, נשמר רק כ-hash |
| Session | יציאה מלאה מהאפליקציה (ברקע) → בכניסה הבאה נדרש PIN שוב |
| שכחת PIN | שחזור עם קוד השחזור → הגדרת PIN חדש |
| אייקון | נשאר גלוי ב-Launcher תמיד |

**כלל ברזל:** שום מנגנון הגנה (Accessibility / Overlay / HOME) לא ימנע פתיחת `שומר אפליקציות` עצמו.

---

## 3. הפעלה ראשונה (Setup)

1. הגדרת PIN (+ אישור).  
2. הצגת קוד שחזור → המשתמש מאשר שצילם.  
3. אשף הרשאות קריטיות (חובה לפני חימוש):  
   - נגישות (שירות המעקב)  
   - גישה לנתוני שימוש  
   - מנהל מכשיר (Device Admin)  
   - הצגה מעל אפליקציות  
   - התעלמות מאופטימיזציית סוללה  
   - התראות (לשירות רקע)  
   - מסכי OEM/אוטו-סטארט אם רלוונטי (מומלץ)  
4. **בזמן האשף:** אין הגנה עצמית / אין חסימת Settings.  
5. בסיום האשף → מעבר ל**רשימה מותרת** (`fromSetup`).  
6. **חימוש מלא רק אחרי לחיצת «אשר»** ברשימה — לא לפני.

---

## 4. רשימה מותרת (לוגיקה יחידה)

### כלל
- **מסומן כמותר** → נפתח.  
- **לא מסומן** → לא נפתח.  
- אין תור «דחוי / ממתין». אפליקציה חדשה שהותקנה לא מתווספת אוטומטית לרשימה.

### פטור מערכת (מינימלי)
- Settings, Launcher(s), SystemUI, IME/מקלדת, Permission Controller, Pixel Settings search (`settings.intelligence`), GMS/חשבון Google, והשומר עצמו.  
- Play Store כחבילה — גלישה מותרת; אפליקציה שהותקנה ממנו עדיין חייבת סימון ברשימה.

### UI רשימה
- חיפוש, בחר הכל / בטל הכל.  
- **שמור / אשר** — שומר את הסימונים; אם `fromSetup` → מדליק הגנה + הגנה עצמית + מנטר.  
- אחרי שמירה → `finish`.

### כשנחסמת אפליקציה
- BACK/HOME + overlay «חסום». בלי לולאות HOME.

---

## 5. מסך ראשי

- סטטוס הרשאות.  
- **מתג הגנה אחד** (רשימה מותרת) — אין מתג «רמה 2».  
- ניהול רשימה / הגדרות / אשף הרשאות.  
- «הפעל הגנה» → רשימה לאישור; חימוש עצמי רק אחרי אשר.  
- כיבוי המתג → מכבה גם חימוש עצמי.

---

## 6. הגדרות (בתוך האפליקציה)

- שינוי PIN (דורש PIN נוכחי).  
- **שחרור נעילת הסרה** (דורש PIN/שחזור):  
  - **לא** מכבה את הרשימה המותרת.  
  - פותח **חלון זמן קצר (~45 שניות)** להשלמת הסרה/ביטול בהגדרות המערכת.  
  - אחרי תום החלון — ההגנה העצמית חוזרת; אם Admin הוסר — בכניסה הבאה מבקשים להפעיל שוב.  
- **נעל שוב** — מבטל את החלון ומבקש להפעיל Device Admin מחדש.

Wi-Fi / הגדרות מערכת כלליות / חיפוש בהגדרות / חשבון Google — **לא** נחסמים. נחסמים רק נתיבים שקשורים להסרת/ביטול השומר.

---

## 7. הגנה עצמית (Kaspersky-style על Pixel)

### מתי פעילה
`setup הושלם` **ו** ההגנה (רשימה מותרת) דלוקה **ו** אין lease פעיל **ו** המשתמש לא בתוך UI רגיל של השומר.

### מה מזוהה כאיום (על האפליקציה שלנו בלבד)

| # | תרחיש | תגובה מיידית | אחר כך |
|---|--------|----------------|--------|
| A | פתיחת **פרטי אפליקציה** (כל האפליקציות, כולל השומר) | — | **מותר** — אין חסימה על עצם הפתיחה |
| B | לחיצה על **הסרה / סגירה ידנית / ארכיון / השבת** בפרטי «שומר אפליקציות» | BACK (הכפתור «לא מגיב») | מסך קוד |
| C | דיאלוג אישור הסרה של השומר (Package Installer וכו׳) | BACK / HOME לפי מקור | מסך קוד |
| D | מסך **ביטול מנהל מכשיר** של השומר | BACK | מסך קוד |
| E | ניסיון **לכבות את שירות הנגישות** של השומר | BACK | מסך קוד |
| F | שחרור יזום מהגדרות באפליקציה | — | PIN → lease ~45 שנ׳ |
| G | לחיצה ארוכה על אייקון במסך הבית | — | **לא** מפעיל PIN |

### מסך הקוד (Challenge)
- Activity ייעודי (לא מסך ה-PIN של הכניסה הרגילה).  
- `singleInstance`, `excludeFromRecents`, `taskAffinity` ריק — **בלי** `noHistory` (כדי שמקלדת/שדה PIN לא יהרסו את המסך).  
- PIN נכון / קוד שחזור → **lease ~45 שניות**.  
- ביטול / יציאה בלי הצלחה → חזרה ל**מסך הבית**.  
- **בלי** לולאות HOME/watchdog.

### מה לא מובטח ב-100%
בלי Device Owner / Knox לא ניתן לחסום OS-level באופן מוחלט. המוצר מתחייב ל**חיכוך גבוה + ניתוב לקוד**, כמו קספרסקי על Pixel.

## 8. תרחישי קצה

| תרחיש | תוצאה רצויה |
|--------|-------------|
| ניסיון חוזר לפתוח אפליקציה חסומה | נשאר חסום |
| יציאה קצרה מהשומר וחזרה | PIN מחדש (session) |
| Upgrade APK | לא נועל משתמש |
| Challenge / מקלדת | שדה PIN נשאר יציב; אפשר להקליד |
| Admin בוטל בכוח בלי lease | הודעה; הרשימה המותרת לא נכבית אוטומטית |
| Safe Mode / ADB uninstall | מחוץ להיקף (מגבלת פלטפורמה); יש Rescue ל-ADB בפיתוח |

---

## 9. זרימות מקצה לקצה

### 9.1 התקנה → הגנה פעילה
התקנה → PIN → שחזור → הרשאות → רשימה מותרת → **אשר** → הגנה + הגנה עצמית פעילים.

### 9.2 ילד פותח אפליקציה אסורה
פתיחה → חסימה + חזרה הביתה / overlay.

### 9.3 אפליקציה חדשה הותקנה
לא ברשימה → לא נפתחת עד סימון + שמירה.

### 9.4 ילד מנסה להסיר את השומר
פרטי אפליקציה נפתחים; **הסרה** / Admin / נגישות → מסך קוד. בלי קוד לא ממשיך. עם קוד → ~45 שנ׳.

### 9.5 הורה רוצה להסיר / לתחזק
נכנס לשומר עם PIN → הגדרות → שחרור נעילת הסרה → ~45 שנ׳ → מסיר בהגדרות המערכת אם רוצה → או «נעל שוב».

### 9.6 הורה רק מנהל רשימה
PIN → רשימה → אשר → חזרה.

---

## 10. מחוץ להיקף (במכוון)

- Device Owner / Profile Owner / MDM  
- Factory reset כתנאי התקנה  
- הסתמכות על Samsung Knox  
- הסתרת האייקון  
- חסימת Wi-Fi / בלוטות׳ / הגדרות כלליות  
- חסימת פרטי אפליקציה של אפליקציות אחרות

---

## 11. קריטריוני קבלה

1. אחרי Setup+אשר: אפליקציה לא ברשימה לא נפתחת.  
2. אין ממשק / לוגיקה של «רמה 2».  
3. פרטי אפליקציה (כולל של השומר) נפתחים; הסרה / סגירה ידנית / ארכיון על השומר → PIN.  
4. ביטול Admin / נגישות של השומר → מסך PIN.  
5. PIN נכון → ~45 שנ׳ אפשר להסיר; אחר כך חוזר קושי.  
6. שחרור הסרה **לא** מכבה את הרשימה המותרת.  
7. תמיד אפשר לפתוח את השומר עם PIN.  
8. בזמן Setup אין בעיטת Settings / lockout.  
9. לחיצה ארוכה ב-Launcher / חיפוש בהגדרות / חשבון Google — לא מעיפים ל-PIN.
